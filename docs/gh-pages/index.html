Rules engine

Tax rules as pure functions

Every tax calculation is a stateless Python function: receives typed inputs, returns typed outputs. No database calls, no side effects — testable in isolation.

tarifa.py
Progressive tax table
UVT-based marginal rates (art. 241 E.T.) — 0% to 39% across 7 brackets. Converts pesos ↔ UVT with rounding.
deducciones.py
Statutory deductions
Housing interest, health insurance, dependents, ICETEX, cesantías — each with its UVT cap and combined 40% ceiling (art. 336).
ganancias_ocasionales.py
Occasional gains
Real estate sales with art. 73 fiscal adjustment, shares (bolsa exemption), inheritance, and lottery — separate 15%/20% rates.
dividendos.py
Dividends (Ley 2277/2022)
Two-step: 35% on untaxed dividends at source, then marginal table on remainder. Handles both gravados and no-gravados.
anticipo.py
Advance tax payment
Art. 807–809: chooses the lower of individual method (25–75%) vs. two-year average. Scales with years of filing history.
sanciones.py
Penalties & interest
Late filing (5%/month, 100% cap), voluntary correction (10%/20%), and daily mora interest — all with the statutory minimum floor.
moneda_extranjera.py
Foreign currency
Art. 269 E.T.: assets valued at year-end TRM; income at transaction-date TRM. TRM supplied by the service layer.
compensaciones.py
Loss carryforward
Art. 147: applies prior-year fiscal losses against cedular income. Returns utilized amount, remainder, and net liquid income.

# rules_engine/tarifa.py — core calculation, no imports from SQLAlchemy
from decimal import Decimal

def calcular_impuesto_uvt(
    base_uvt: Decimal,
    tabla: list[tuple[Decimal, Decimal | None, Decimal, Decimal]],
) -> Decimal:
    """
    Applies the progressive UVT table.
    Returns tax in UVT — convert to pesos with a_pesos().
    Each tuple: (lower_bound, upper_bound, marginal_rate, base_tax_uvt)
    """
    for inf, sup, tarifa, base in tabla:
        if sup is None or base_uvt <= sup:
            return base + (base_uvt - inf) * tarifa
    return Decimal("0")

def calcular_renta_exenta_laboral(
    ingreso_salarios_pesos: Decimal,
    *,
    porcentaje: Decimal,       # Decimal("0.25")
    tope_uvt: Decimal,
    uvt: Decimal,
) -> Decimal:
    base = ingreso_salarios_pesos * porcentaje   # Decimal × Decimal ✓
    tope = tope_uvt * uvt
    return min(base, tope)
# core/json_encoder.py — one place, covers all endpoints + all JSONB fields
import json
from decimal import Decimal
from fastapi.responses import JSONResponse

def _default(obj):
    if isinstance(obj, Decimal): return str(obj)
    raise TypeError(f"Not serializable: {type(obj)}")

def dumps_decimal(data) -> str:
    return json.dumps(data, default=_default)

class DecimalJSONResponse(JSONResponse):
    def render(self, content) -> bytes:
        return json.dumps(content, default=_default,
            separators=(",", ":"), ensure_ascii=False,
        ).encode("utf-8")

# main.py — registered once, covers every endpoint automatically
app = FastAPI(default_response_class=DecimalJSONResponse)

# services/parametros_service.py — float→Decimal at the boundary
class ParametrosVigentes:
    """
    When params come from JSONB (production), PostgreSQL
    deserialises them as Python float — JSON has no Decimal.
    The _d() helper converts at the boundary so every attribute
    the rules engine sees is already Decimal.
    """
    def __init__(self, datos: dict):
        def _d(v) -> Decimal:
            if isinstance(v, Decimal): return v
            return Decimal(str(v))   # str() avoids IEEE-754 drift

        self.UVT  = _d(datos["uvt"])           # e.g. Decimal("49799")

        )

Key design decisions

Decision 1
Params as data, not code
UVT, tax table, and all caps live in PostgreSQL, managed by the Admin UI. No redeployment for next fiscal year — add a new DB record.
Decision 2
Decimal everywhere
Decimal("0.25") not 0.25. IEEE-754 drift is unacceptable in a tax return filed with the DIAN. 10 bugs found and fixed.
Decision 3
Backend is the source of truth
The wizard may show estimated results for UX — but the value persisted to resultado_liquidacion always comes from the API.
Decision 4
Audit trail by design
Every write generates an auditoria_cambio row with actor, action, and before/after JSONB. Includes bulk imports.
